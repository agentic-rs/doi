# Optional Reading view

Reading view is a local, derived layout of source PDF rectangles. The PDF remains the canonical document: vector figures, equations, captions, and typography are rendered by PDF.js at the current display scale. This first version does not reflow text or offer a separate font size.

A bounded analysis bitmap and the text geometry protect content while detecting empty outer margins, paragraph gaps, and clear column gutters. Gutter width is relative to the body font, and substantial prose must appear independently on both sides. Each crop recombines its own text items so narrow columns cannot merge into one sentence. Splits pass through empty corridors; ambiguous regions retain their original arrangement. Figures include their labels and captions. A uniquely numbered figure moves after the first clear single-number Figure/Fig. reference; unmatched or ambiguous figures retain source order. Scanned pages remain cropped originals without OCR. Collapsed, reversed, missing, or nonfinite font ascent/descent use a shared nonzero em box in crop analysis, selectable text ownership, and line splitting; valid font metrics retain their values.

Tall rotated margin stamps are isolated only through a blank corridor outside all horizontal body text. Their ink stays intact in a tightly cropped strip after the page body; narrow original strips fit compactly rather than enlarging to the full reader width. Plot labels within figures remain attached to their original region. This lets a first page's full-width metadata and two-column body be segmented independently of its vertical arXiv stamp.

Analysis runs one page at a time, can be cancelled by returning to PDF, and reports progress. Rust stores the completed layout in SQLite keyed to the cached PDF hash and extractor version. Invalid or stale derived data is rebuilt. Cache failures do not block reading.

Each existing crop has a semantic `block_type`: `content`, `equation`, `graph`, `table`, `reference`, `title`, or `others`. A small label appears above the crop even when reading controls are hidden. It scales with the paper and is excluded from PDF selections. Titles include document and section headings; graphs include figures, diagrams, images, and captions. Standalone mathematics is an equation, while inline mathematics and citations remain part of content. Bibliography entries use Reference; their heading uses Title when it has its own crop. Authors, affiliations, running headers, page numbers, scans without text, algorithms, and uncertain mixed regions use Others.

Classification uses the existing local text geometry and analysis bitmap, plus document context for bibliography boundaries and repeated headers. It does not call AI or perform another PDF render. The operational `kind` remains separate from its label. Classification labels existing crops rather than splitting them into semantic units, so a crop can contain several paragraphs or mixed material. Bibliography and running-header context can relabel Content, Title, and Others; recognized Graph, Table, and Equation crops retain their type while still updating section boundaries. Larger unnumbered section headings end bibliography context even inside mixed crops. Layout cache version 5 rebuilds earlier versions with margin-stamp separation and typography-aware bibliography boundaries, retaining version 4's narrow-column detection and valid fallback font bounds. Saved papers, notes, chats, and annotation schemas are unchanged.

Every block retains its source page and PDF-space rectangle. Selections follow displayed block order and produce the existing annotation schema's original PDF quads. Reading positions additionally retain the view mode and block ID; source page fractions determine the destination if a layout rebuild reuses that ID for a different crop. Matching IDs break ties at shared boundaries and in removed whitespace. Legacy positions default to PDF. Source links and Back/Forward preserve the passage across view changes. Figure enlargement uses staged, scoped PDF zoom so its toolbar remains fixed.

Content blocks offer a small Split lines toggle alongside View in PDF. Each long original PDF line first tries two parts at a measured word boundary near half the crop width. If the printed cut is unsafe, that line tries three parts near thirds. A line that still cannot split remains whole and small within the block; other lines continue to split. Short lines stay intact. Two- and three-part lines share the fitting scale of the proposed two-part layout. The rendered source crop supplies printed line strips, which retain the original glyphs, font, and spacing. Paragraph gaps remain once. All parts stay inside one block with its original ID, notes, and reference strip. Preparation keeps the previous bitmap visible; unmeasurable text or rotated pages retain the original crop with an explanation.

PDF font ascent/descent supplies vertical ink bounds, while an untransformed, hidden PDF.js text layer measures word boundaries and original character rectangles. Explicit PDF spaces and font changes are retained. Split selectable runs have exactly one displayed copy, including cuts inside a PDF text item. Selections recover the exact source character quads; note highlights, links, saved positions, and Back/Forward use the same source-to-display piece mapping, including uniform scaling for retained small lines. An offscreen pending destination is brought into view before its exact mapping is restored. Layout-preservation anchors yield when the user scrolls during preparation; saved destinations and zoom anchors retain their explicit intent. The original PDF and annotation schema remain canonical.

Before replacing the visible bitmap, raster checks validate word gaps and retained ink independently for each source line because browser text metrics can differ slightly from the PDF. Safe chosen cuts stay stable through later renders. Adjacent lines whose vertical boundary crosses printed ink remain together as one small original strip so a superscript or overlapping glyph is not divided. Bitmap, selectable text, and source mappings commit together at the final dimensions; a different line layout cannot reuse an older mapping merely because its source viewport is unchanged. Cancelled or failed work cannot clear the last completed page.

Within independently bounded rows, raster ink expands underestimated font ascent/descent before continuation strips are formed. This preserves capitals and descenders in subset fonts that report nonzero but incomplete em bounds, while retaining whole rows when their vertical boundaries intersect ink. Insignificant floating-point roundoff in strip coordinates reuses the completed layout object so selectable text and mapping readiness remain synchronized.

SQLite schema version 5 stores user-owned block preferences separately from the disposable Reading layout cache. Async commands load, save, and reset choices keyed to the PDF hash, source page, and source rectangle (within 0.01 PDF points), rather than derived block IDs. Layout rebuilds preserve matching choices, another PDF hash cannot inherit them, and deleting a paper cascades its preferences. Failed loads can be retried; failed writes retain the previous visible choice. Browser development keeps choices in memory.

Reading view's toolbar also offers a Split all lines icon for the current paper. It applies the same two-/three-part layout to every Content block; titles, figures, tables, equations, references, and other blocks keep their original layout. When every Content block has split lines enabled, the icon restores their original lines. Individual block toggles remain available; a mixed selection makes the toolbar action enable all again. One async batch command writes only changed choices in a single SQLite transaction using the existing preference schema. Saving disables split controls, failures preserve all previous choices, and the reader retains its original PDF source point through simultaneous height changes. Split rendering remains lazy as blocks approach the viewport.

On native iPhone and iPad, a rightward drag beginning within 24 CSS pixels of the left screen edge uses the existing Back history, or closes the current paper/tab when that history is exhausted. The action commits on release after a deliberate horizontal drag; short, reversed, interrupted, vertical, or multi-touch sequences do not navigate. The fixed Back/Close indicator performs no PDF rendering or page-layout reads while moving. Dialogs, selections, editing, pending document operations, and orientation transitions disable the gesture, and a paper/history change invalidates an in-flight swipe. Mac navigation and stored schemas are unchanged.

Reference details and other dismissible dialogs retain their backdrop through pointer release. An outside click is consumed before dismissal, so it cannot activate a paper link underneath. Pressing inside the dialog and releasing outside, or cancelling a pointer gesture, does not dismiss it. A subsequent independent click works normally; no global click delay is used. Paper information and Settings share the same backdrop behavior, including their existing busy-state dismissal guards.

Saved notes appear as expandable cards beneath their source blocks on iPhone and iPad. Each individual annotation quad is intersected with the block's source rectangle; a note spanning blocks appears once per matching block. Its passage action uses that block's matching anchor. An unmatched note remains available in the all-notes panel rather than being attached to a guessed passage. The Mac reader uses a docked sidebar with one card per note and keeps paper navigation, selection, and zoom active.

Collapsed cards show the first line of the saved content. Expansion reveals the note, quoted passage, and editing, deletion, and source-navigation actions. AI notes preserve their original answer and provenance. Inline cards share the paper's scale; sidebar cards retain normal UI sizing. A visible crop or note anchors scroll position through card height changes. Note updates and edit-state changes wait until an active pinch settles, and note-bearing articles participate in the same preview as references even when their source bitmap is offscreen. Card text is excluded from PDF selection capture. Existing annotation records, storage commands, and sidecars are unchanged.
