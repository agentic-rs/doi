# Optional Reading view

Reading view is a local, derived layout of source PDF rectangles. The PDF remains the canonical document: vector figures, equations, captions, and typography are rendered by PDF.js at the current display scale. This first version does not reflow text or offer a separate font size.

A bounded analysis bitmap and the text geometry protect content while detecting empty outer margins, paragraph gaps, and clear column gutters. Splits pass through empty corridors; ambiguous regions retain their original arrangement. Figures include their labels and captions. A uniquely numbered figure moves after the first clear single-number Figure/Fig. reference; unmatched or ambiguous figures retain source order. Scanned pages remain cropped originals without OCR.

Analysis runs one page at a time, can be cancelled by returning to PDF, and reports progress. Rust stores the completed layout in SQLite keyed to the cached PDF hash and extractor version. Invalid or stale derived data is rebuilt. Cache failures do not block reading.

Each existing crop has a semantic `block_type`: `content`, `equation`, `graph`, `table`, `reference`, `title`, or `others`. A small label appears above the crop even when reading controls are hidden. It scales with the paper and is excluded from PDF selections. Titles include document and section headings; graphs include figures, diagrams, images, and captions. Standalone mathematics is an equation, while inline mathematics and citations remain part of content. Bibliography entries use Reference; their heading uses Title when it has its own crop. Authors, affiliations, running headers, page numbers, scans without text, algorithms, and uncertain mixed regions use Others.

Classification uses the existing local text geometry and analysis bitmap, plus document context for bibliography boundaries and repeated headers. It does not call AI or perform another PDF render. The operational `kind` remains separate: figure relocation, enlargement, source rectangles, block IDs, and source order are unchanged. This first pass labels existing crops rather than splitting them into semantic units, so a crop can contain several paragraphs or mixed material. Bibliography and running-header context can relabel Content, Title, and Others; recognized Graph, Table, and Equation crops retain their type while still updating section boundaries. Layout cache version 3 requires the type on every block and automatically rebuilds earlier versions, including version 2's incorrect Figure 3 label. Saved papers, notes, chats, and annotation schemas are unchanged.

Every block retains its source page and PDF-space rectangle. Selections follow displayed block order and produce the existing annotation schema's original PDF quads. Reading positions additionally retain the view mode and block ID, with source page fractions as a fallback; legacy positions default to PDF. Source links and Back/Forward preserve the passage across view changes. Figure enlargement uses staged, scoped PDF zoom so its toolbar remains fixed.

On native iPhone and iPad, a rightward drag beginning within 24 CSS pixels of the left screen edge uses the existing Back history, or closes the current paper/tab when that history is exhausted. The action commits on release after a deliberate horizontal drag; short, reversed, interrupted, vertical, or multi-touch sequences do not navigate. The fixed Back/Close indicator performs no PDF rendering or page-layout reads while moving. Dialogs, selections, editing, pending document operations, and orientation transitions disable the gesture, and a paper/history change invalidates an in-flight swipe. Mac navigation and stored schemas are unchanged.

Reference details and other dismissible dialogs retain their backdrop through pointer release. An outside click is consumed before dismissal, so it cannot activate a paper link underneath. Pressing inside the dialog and releasing outside, or cancelling a pointer gesture, does not dismiss it. A subsequent independent click works normally; no global click delay is used. Paper information and Settings share the same backdrop behavior, including their existing busy-state dismissal guards.

Saved notes appear as expandable cards beneath their source blocks on iPhone and iPad. Each individual annotation quad is intersected with the block's source rectangle; a note spanning blocks appears once per matching block. Its passage action uses that block's matching anchor. An unmatched note remains available in the all-notes panel rather than being attached to a guessed passage. The Mac reader uses a docked sidebar with one card per note and keeps paper navigation, selection, and zoom active.

Collapsed cards show the first line of the saved content. Expansion reveals the note, quoted passage, and editing, deletion, and source-navigation actions. AI notes preserve their original answer and provenance. Inline cards share the paper's scale; sidebar cards retain normal UI sizing. A visible crop or note anchors scroll position through card height changes. Note updates and edit-state changes wait until an active pinch settles, and note-bearing articles participate in the same preview as references even when their source bitmap is offscreen. Card text is excluded from PDF selection capture. Existing annotation records, storage commands, and sidecars are unchanged.
